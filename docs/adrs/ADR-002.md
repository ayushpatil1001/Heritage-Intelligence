# ADR-002: Kiosk Offline-First Architecture & Ephemeral Session Privacy

## Status
Accepted

## Context
Museum kiosks operate in public institutional environments with varying network reliability and hundreds of daily visitors touching shared screens. Two primary challenges arise:
1. **Network Fluctuations:** If internet or WAN connectivity drops, museum visitors should not experience broken screens or loading failures.
2. **Session Privacy & Hygiene:** When a visitor leaves a kiosk, their search queries, reading history, and notes must not leak to the subsequent visitor. Additionally, visitors need a zero-friction method to transfer their research to personal mobile devices without creating accounts or entering credentials on a public screen.

## Decision
1. **Local-First Caching & Dual Database Fallback:**
   - The system bundles SQLite / embedded static seed caches containing all 30 foundational items, 25 timeline events, and 4 curated stories.
   - Core API endpoints automatically serve local assets when offline or when external AI endpoints are unreachable (`AI_MODE=mock`).
2. **60s Countdown & 90s Inactivity Hard Session Wipe:**
   - An inactivity monitor tracks user touch, pointer, and keyboard events.
   - At 60 seconds of inactivity, an accessible dialog displays a 30-second countdown with an audible cue.
   - At 90 seconds, all active states, collection binders, and search inputs are completely cleared, and the screen resets to the ambient attract loop.
3. **7-Day Ephemeral Transfer Tokens:**
   - Visitors can generate a dynamic QR code (`/collections?token=...`) encoding an encrypted 7-day ephemeral token.
   - No personal names, emails, or credentials are required. The user's phone reads the collection without registration.

## Consequences
- **Positive:** Uninterrupted museum operation, zero visitor privacy leakage, effortless mobile continuity.
- **Negative:** Kiosk state is strictly ephemeral; unsaved local notes are cleared on session timeout by design.
